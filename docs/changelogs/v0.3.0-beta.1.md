# v0.3.0-beta.1 technical changelog

The [public release note](../releases/v0.3.0-beta.1.md) summarizes the first
direct-IP beta. This document records the host-role, gameplay, renderer, and
release changes behind that promotion.

## Context and root causes

The alpha required a host to participate as a racer, which made dedicated event
direction awkward and consumed a player slot. Beatblock's normal pause path
could also interrupt an active online chart. The OBS pipeline still needed its
state reconciled around native gameplay timing, delayed telemetry, pre-roll,
and source recreation before the project could be treated as a broader beta.

## Implementation details

### Hosting and race control

- Added a **Play** or **Direct** choice during room creation. A directing host
  controls the room without appearing in rankings or consuming a racer slot,
  and can switch role before a later race.
- Blocked Escape and controller pause actions during online gameplay while
  retaining Beatblock's normal offline pause behavior.
- Completed ordered setlist management, continuation, participant inspection,
  approval, exact chart verification, and role-aware next actions.

### Native OBS output

- Rebuilt renderer export around Beatblock's native gameplay timing instead of
  reconstructing animation state outside the game.
- Preserved final-shaded Full and palette-correct Clean output, including
  authored backgrounds, video, entities, effects, HUDs, and Results.
- Aligned delayed telemetry, tap judgements, paddle state, pre-roll, and the
  first scoring-note barrier across assigned streams.
- Kept four independently configurable Stream A–D slots with bounded delay,
  720p/1080p and 30/60 fps controls, Commentator mirrors, health reporting, and
  deterministic visual states.

### Runtime, installer, and release contract

- Retained host authority, authenticated SPAKE/QUIC sessions, owner-only IPC,
  loopback credentials, bounded queues/files, and explicit shutdown.
- Hardened chart consent, installer rollback, direct-launch ownership, Lovely
  preservation, OBS replacement, and elevated-helper path validation.
- Standardized the self-contained installer name and kept generated binaries
  outside version control.
- Pinned third-party Actions and native dependencies, audited the supported
  Windows Rust graph, verified generated protocol/mod payloads, and bound the
  OBS DLL to reviewed source.
- Required the pushed prerelease tag to match the package version exactly.

## Migration and compatibility

All participants should update to the beta before creating a room. Close
Beatblock and OBS, install into the selected game folder, then restart OBS
before testing Player Stream sources. Existing user data, unrelated mods, and
installer rollback controls are preserved.

## Validation evidence

The promotion retained protocol, Rust, Lua, UI, renderer, stress, installer,
archive, PE, checksum, and OBS-provenance gates. Native Full/Clean output and
the synchronized first-note barrier were exercised by deterministic visual and
renderer tests. Release publication remained environment-gated and operated
only on the reviewed workflow artifact.

## Known limitations

The beta designation did not certify the physical WAN, production audio route,
or long-duration four-renderer environment. Those trials remained required
before a stable designation.
