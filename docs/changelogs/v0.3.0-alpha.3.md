# v0.3.0-alpha.3 technical changelog

The [public release note](../releases/v0.3.0-alpha.3.md) summarizes the
player-facing changes. This document retains the implementation and release
evidence behind the protocol-v3 alpha.

## Context and root causes

The preceding prototype mixed room, chart, commentator, and broadcast actions
across transitional screens. Its renderer could expose palette-index or
incomplete frames rather than the delayed final player view, while renderer
startup and first-note timing did not share one explicit synchronization
barrier. Installer upgrades also needed ownership-aware rollback, and the
network, IPC, local API, file, and release paths lacked consistent resource and
provenance contracts.

## Implementation details

### Online and Commentator workflow

- Replaced the transitional menus with Room, Setlist, Broadcast, History,
  Settings, and Help workspaces.
- Added host-managed Commentator access, chart transfer, participant
  inspection, persistent selection, bounded error details, native keyboard
  callbacks, active keyboard layouts, and Unicode-safe editing.
- Made room state and scoring host-authoritative. Pending participants,
  spectators, and unknown peer message kinds cannot mutate gameplay or publish
  host-owned snapshots.
- Authenticated both sides of the SPAKE exchange and bound the observed
  self-signed QUIC certificate to the password-authenticated transcript.
- Required exact, expiring, one-use chart-archive authorization. Executable or
  script content still requires a separate consent decision.

### Native OBS rendering

- Defaulted four renderer slots to a delayed 1280×720, 60 fps Full view.
- Published final palette/accessibility shading and screen-space effects,
  including chart backgrounds, video, entities, blocks, feedback, HUDs, and
  native Results.
- Warmed each chart from delayed pre-roll and held source release until its
  first scoring note. Remote time is applied before native processing, mouse
  state is rebuilt before paddle motion, and the paddle is seeded only at the
  synchronized release boundary.
- Replayed source-authored tap edges at their original offset-adjusted beat with
  same-frame raw input as a fallback.
- Prevented a first sample from bypassing delay, rejected reconfiguration after
  countdown start, and pinned renderer DPI to 1.0.

### Installer, runtime, and release hardening

- Added reversible direct-launch support for isolated copies without modifying
  Steam-managed launch behavior.
- Preserved a compatible Lovely Injector and removed only positively identified
  legacy Beatblock Together files.
- Detected running OBS before replacing its loaded plugin, improved elevated
  diagnostics, and validated dashboard and renderer payloads during repair.
- Replaced URL query credentials with a 256-bit loopback bearer credential and
  token-bearing WebSocket subprotocol.
- Used an owner-access-controlled Windows named pipe with partial-I/O handling,
  bounded frames, and bounded queues. Startup reads, logs, caches, configuration
  replacement, and credential replacement received equivalent bounds.
- Bound the generated OBS DLL to reviewed source with a versioned SHA-256
  manifest, verified exact mod ZIP contents, regenerated protocol v3, pinned
  Actions and native inputs, and separated read-only builds from gated
  publication.

## Migration and compatibility

This release moves peers and generated payloads to protocol v3. Operators must
close Beatblock and OBS, update the selected game installation, and restart OBS
before using the source. Configure and assign renderer streams before starting
a synchronized countdown; an active slot may still be stopped during a race.
The installer transaction preserves user data and unrelated mods and offers
repair, restore, and uninstall paths.

## Validation evidence

- Protocol, release-workflow, patch-validation, mod-package, installer, and Rust
  unit/integration suites passed.
- Release-mode direct-room, renderer, export, and journal stress tests passed.
- Rust formatting and Clippy ran with warnings denied.
- Twenty-six deterministic 600×360 UI states matched with zero changed pixels.
- The LÖVE GPU/readback harness verified the final shaded 320×180 frame, opaque
  aspect-ratio bars, frame publication, and drop counting.
- x64 PE, exact ZIP, checksum, generated schema, and OBS source-provenance
  verification passed.
- The current-source protocol-v3 lifecycle, mutex, shutdown, parent-exit, and
  no-console checks recorded a 12,980,224-byte idle working set against the
  31,457,280-byte limit.

## Known limitations

This alpha did not complete the physical two-machine WAN or long-duration OBS
audio/video certification trials. Automated rendering and isolated-machine
checks cannot establish driver-specific capture, production network, or
long-duration broadcast behavior.
