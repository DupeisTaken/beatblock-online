## Context and root causes

- **#20:** the OBS video path did not declare the display/sRGB contract of the
  supplied RGBA bytes, while audio lifetime and routing were coupled to each
  video scene item. Hidden renderers could also remain audible on the desktop.
- **#21:** per-player reconstruction produced only that player's hits. Mixing
  those channels duplicated the song and could not produce one canonical
  song-plus-all-positive-hits feed.
- **#22:** update discovery opened GitHub Releases but could not securely
  download, validate, promote, relaunch, or roll back an installer update.
- **#23:** long GitHub Release descriptions mixed player-facing changes with
  implementation detail and lacked a navigable technical history.
- **#24:** game and OBS process/component state was sampled only at startup,
  forcing users to restart the installer after closing either application.
- **#25:** the fixed header repeated `BBT` and `ONLINE`, obscuring the product
  name and lifecycle state.
- **#26:** abbreviated Settings controls fit the 600×360 canvas but made state
  and actions difficult to understand.
- **#29:** issue #18 contained setlist text, but one-off chart replacement and
  ordered-set editing still shared an ambiguous workspace.

## Implementation details

### OBS video and independent audio — #20

- Player Stream is video-only and declares an sRGB single-texture source.
  Frame-ring header v3 identifies display/sRGB RGBA8 bytes and rejects unknown
  pixel contracts.
- Beatblock Online Audio exposes separate A-D/Autoplay sources with independent
  0–2000 ms synchronization and status.
- Renderer desktop sessions are discovered and muted by exact child PID, not
  executable name. The prior mute state is restored before normal teardown and
  retried after abnormal exit; bounded discovery also covers late-created audio
  sessions.
- Automatic desktop isolation is enabled by default with a Settings fallback
  for drivers whose process loopback follows session volume. The host game and
  unrelated processes are outside the selection boundary.
- Review additionally fixed a non-Windows worker-return compile error and
  isolated the autoplay renderer's APPDATA/Lovely profile so renderer settings
  cannot leak into the host or other streams.

### Song-plus-perfect-hits autoplay — #21

- Broadcast can launch one optional audio-only Autoplay renderer before a race.
  It follows the featured renderer's delayed clock and allocates neither video
  canvases nor a frame ring.
- Native note behavior produces positive Block, Hold, Bounce, Side, tap, and
  ExtraTap hitsounds. Mines and mine-holds are avoided; no custom miss, barely,
  or duplicate hitsound path is introduced.
- The disposable profile disables Beatblock save paths before applying
  hitsound/music/SFX options in memory. Ordinary renderer profiles remain
  unchanged.
- Optional protocol-v3 plan fields are backward compatible. Enablement and
  clock-source changes are locked during countdown/gameplay and require an
  active featured renderer.

### Verified installer self-update — #22

- **Update Installer** selects exactly one `BeatblockOnlineInstaller.exe` and
  one `SHA256SUMS.txt` from the chosen semantic-version release.
- The client requires trusted GitHub HTTPS hosts, bounds metadata, checksum,
  installer, redirect, connection, transfer, and version-probe resources, and
  rejects missing or duplicate assets.
- The downloaded executable must match both GitHub's SHA-256 asset digest and
  the exact checksum-list entry, contain an x64 PE header, and report the
  selected package version.
- A UUID-bound receipt records version, hash, staged path, managed destination,
  and old PID. Every handoff revalidates real non-symlink directories and may
  promote only the app-managed maintenance copy; an arbitrary launch location
  is never overwritten.
- Promotion uses exclusive temporary creation and a previous-copy backup. The
  finalizer waits for the old PID, launches the promoted copy, and retains the
  backup until the new native window acknowledges a random readiness token.
  Failed promotion, launch, or readiness restores the previous managed copy.
- Self-update is refused while elevated to avoid combining administrator
  authority with user-writable update paths. Process-open failures are not
  mistaken for an already-exited parent, and a wedged `--version` subprocess is
  killed and reaped on its deadline.
- Updating the installer does not modify game files. The unknown-publisher
  warning remains because integrity/provenance checks are not Authenticode.

### Release documentation — #23

- Alpha.3 through beta.5 have concise public notes and paired technical
  changelogs. The release index links both documents for every supported
  historical note.
- The release workflow validates required sections, note size, pair parity,
  index coverage, and links safe for a GitHub Release body.
- Installer update results expose **View release notes** and **All releases**.
- Compatibility language consistently says that newer structurally valid
  builds may be accepted but remain unverified until the exact displayed
  version and bracketed token pass the compatibility suite.

### Live Beatblock and OBS status — #24

- **Refresh game & OBS status** updates target inspection, Beatblock process
  state, OBS component state, and OBS process state together; the Components
  page reuses the same refresh path.
- No background polling was added. Beatblock mutations are disabled while
  `Beatblock.exe` runs, and OBS integration changes are disabled while
  `obs64.exe` runs. Backend transactions enforce the same interlocks.
- Windows ToolHelp snapshot failures propagate instead of reporting a process
  absent. The UI fails closed by disabling the related mutation; command paths
  return the inspection error.

### Header and Settings clarity — #25 and #26

- The header now uses `BEATBLOCK ONLINE` on the left and
  `vX / READY`, `vX / STARTING`, or `vX / OFFLINE` on the right.
- Settings uses full `HUD`, `RUN CHECKS`, `BUILD`, and `REQUESTS` labels in a
  two-column state grid. `CLEAR TRANSFER CACHE` and renderer desktop mute remain
  explicit full-width controls.
- Mouse, keyboard/controller focus order, read-only state, long text, and every
  Settings combination remain within the 600×360 rendering contract.

### Single-chart and ordered-set workflows — #29

- Global **SELECT CHART** opens a dedicated OFFICIAL/CUSTOM source picker.
  Replacing a non-empty ordered set requires confirmation before leaving Online
  for Beatblock's selector.
- Setlist is exclusively an ordered queue: one full-width panel shows six rows
  with Order, Chart, Variant, and NOW/NEXT/QUEUED/DONE State columns.
- Selection follows stable entry IDs across move, removal, and snapshot
  refresh. The first added row becomes active; later additions preserve the
  locally verified active chart.
- Only rows strictly after the active chart can reorder. Completed/current
  boundaries are enforced by both UI and room state, editing is disabled during
  countdown/gameplay, and non-hosts receive a read-only view.
- Results exposes one global **NEXT CHART** action. Review caught and fixed an
  active-row move path that could otherwise strand an unplayed chart behind the
  cursor and skip it.

### Issue reporting

- Compatibility reports now apply `bug` plus `compatibility`, collect the exact
  displayed version/build token and failure stage, and require an open/closed
  duplicate search.
- The generic bug form routes installer, runtime, protocol, chart/result,
  dashboard, and OBS/audio reports and collects role/OBS context.
- README and contributor guidance link every guided form and retain
  `blank_issues_enabled: false`.

## Migration and compatibility

Close Beatblock and OBS before installing. Existing Player Stream scene items
become video-only, so add and route the desired A-D or Autoplay audio source
once after upgrading. Verify production-machine audio routing before an event.

The verified Beatblock baseline remains
`1.7.1a (Early Access)[d40b7083]`. Later structurally valid builds may be
accepted but remain unverified until the exact version and bracketed token pass
the compatibility suite. Protocol version 3, the setlist wire format, direct-IP
room behavior, and the 600×360 dashboard canvas are unchanged.

Installer self-update replaces only its app-managed maintenance copy. A
manually downloaded/external launcher remains untouched. Run self-update
without administrator elevation; normal install/repair operations may still
request UAC when they need to modify protected locations.

## Validation evidence

- OBS exact-PID isolation, autoplay Lua behavior, renderer lifecycle, protocol,
  runtime, command, stress, packaging, formatting, and static checks passed.
- Dashboard room/model regressions cover single-chart replacement, lifecycle
  advancement, stable selection, active/completed boundaries, and queue
  removal. All 44 versioned UI scenarios reproduced at zero differing pixels,
  and shared/standalone/BeatblockPlus Lua copies match.
- Installer validation covers asset completeness, trusted URLs, size bounds,
  dual hashes, x64/version identity, confined receipts, exclusive handoffs,
  promotion rollback, readiness timeout, elevated refusal, fail-closed process
  enumeration, and bounded subprocess cleanup. Thirteen updater tests, three
  installer CLI tests, installer-UI compilation, and 22 release-workflow
  contract tests passed.
- Pull-request CI passed on the final OBS, dashboard, installer, and issue-form
  SHAs, and combined dashboard-plus-installer main CI passed. The complete
  payload-backed beta.5 trial passed 165 library tests plus all binary,
  integration, stress, packaging, lifecycle, UI, maximum-room, and benchmark
  gates. The tag-triggered release build remains the final authority for the
  published artifacts.

## Known limitations

- Physical OBS 32.1.2 color accuracy, A-D/Autoplay routing, process-loopback
  behavior after desktop mute, A/V alignment, and ten-minute drift/drop results
  remain tracked in
  [#28](https://github.com/DupeisTaken/beatblock-online/issues/28).
- Automated updater seams cannot substitute for a disposable real-machine
  download/promote/relaunch trial, antivirus/locked-destination behavior, or
  live Beatblock/OBS close-and-refresh testing on every supported Windows host.
- GitHub artifact attestations and checksums establish workflow provenance and
  integrity, but the installer remains unsigned and Windows may display
  **Unknown publisher**.
- Later Beatblock builds, WAN topologies, and long-duration maximum-room
  operation require validation in each target event environment.
