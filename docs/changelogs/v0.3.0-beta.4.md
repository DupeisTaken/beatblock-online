# v0.3.0-beta.4 technical changelog

The [public release note](../releases/v0.3.0-beta.4.md) summarizes issues
[#15](https://github.com/DupeisTaken/beatblock-online/issues/15) through
[#19](https://github.com/DupeisTaken/beatblock-online/issues/19).

## Context and root causes

- **#15:** Executable allowlisting would force a new Online release for routine
  Beatblock updates, while rooms still needed an exact runtime build identity.
- **#16:** A Player missing the locked custom chart had no safe, explicit way to
  request the exact host archive.
- **#17:** The header presented protocol v3 like an application version and did
  not distinguish tested from detected Beatblock identity.
- **#18:** Setlist labels and action placement overflowed the fixed 600×360
  dashboard.
- **#19:** Player Stream audio targeted the visible game rather than the
  individually delayed renderer responsible for each A–D video stream.

## Implementation details

### Accepted newer builds and strict rooms — #15

- The installer accepts structurally valid Beatblock installations instead of
  requiring a pre-published executable hash.
- Once the game starts, the adapter sends the complete upstream version and
  bracketed build token. Deterministic full-version and content-digest
  fallbacks cover changed or missing labels.
- Rooms require exact build identity by default. Hosts may create an
  **Allow Any** casual room or relax a strict room before a race; relaxation is
  one-way for that room.
- Build identity participates in the password-authenticated handshake before
  roster admission. Reconnect retains the original normalized identity.

### Consent-aware chart transfer — #16

- An unverified Player may request the current locked chart manually; the host
  may enable one automatic request per lock.
- Download approval remains receiver-owned. Automatic request does not bypass
  archive consent.
- The host rechecks connection, admission, role, verification, lock identity,
  and transfer policy before queueing, after the archive-worker queue, and
  after packaging so stale work cannot survive a room-state change.

### Product and compatibility identity — #17

- The header shows the Online product version.
- Settings separates Online version, protocol version, tested Beatblock
  baseline, and currently detected version/build.
- GitHub Release titles add the tested baseline while Git tags remain semver
  for update tooling.
- Contract tests keep Node, Rust, Lua, protocol, UI, packaging, and release
  metadata aligned.

### Setlist containment — #18

- Reorganized add, remove, and continuation controls within 600×360.
- Constrained chart names, variants, statuses, validation, and disabled text to
  their columns.
- Added deterministic states for setlist, validation, long errors, transfer,
  host, Settings, and Broadcast views.

This change fixed overflow but did not fully separate one-off chart selection
from ordered setlist management; that broader workflow redesign remains
follow-up work.

### Per-renderer OBS audio — #19

- Each Player Stream creates a private Application Audio Capture child targeting
  its stable `Beatblock Online Renderer A-D` process.
- Audio follows the delayed renderer clock, so the per-stream fine-sync default
  is 0 ms and remains independently adjustable.
- Missing Application Audio Capture support degrades to video-only.
- Stable renderer labels preserve A–D assignments across normal scene/source
  recreation.

Additional review fixes corrected SDL3 minimization, moved fallback game
content hashing off the asynchronous runtime with a 64 KiB buffer, and closed a
chart-transfer eligibility race while packaging was queued.

## Migration and compatibility

Close Beatblock and OBS before updating and restart both afterward. The release
was verified against `1.7.1a (Early Access)[d40b7083]`. The installer accepts
newer structurally valid builds, but those builds are unverified until their
exact displayed version and bracketed token pass the compatibility suite.
Strict rooms remain the default; **Allow Any** is for intentional casual
testing. Existing OBS scenes need their A–D assignments and audio routes
reviewed on the production machine.

## Validation evidence

- Protocol and real-QUIC tests cover strict-build joins and reconnect identity.
- Chart-transfer protocol, room, command, and UI tests cover eligibility,
  consent, queued-state revalidation, and stale work.
- Release-contract tests cover tag/version equality, compatibility-title
  generation, and tagged-source checkout.
- Thirty-one versioned LÖVE screenshots cover dashboard, setlist, validation,
  transfer, Settings, and Broadcast states at zero differing pixels.
- Native OBS target-selection and source/localization checks cover private audio
  child selection, controls, and fallback.

## Known limitations

Windows process-loopback capture copies renderer audio but does not silence that
renderer on the desktop. Broadcasters must use the documented mixer or routing
procedure. Physical OBS routing, multi-network WAN behavior, later Beatblock
builds, and long-duration four-renderer operation remain unverified on each
target event environment.
