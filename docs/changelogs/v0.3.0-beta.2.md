# v0.3.0-beta.2 technical changelog

The [public release note](../releases/v0.3.0-beta.2.md) summarizes the
correctness update. This document records the run-state and broadcast defects
that were fixed.

## Context and root causes

Duplicate display names were silently rewritten, leaving the rejected client
in an unclear reconnect state. Retries and reconnects did not have a complete
attempt identity, so late events could contaminate a replacement run. Native
Mine/MineHold counters and the same-frame Results transition could briefly
produce states that the host mislabeled impossible or incomplete. OBS values
could come from replay-derived state rather than the delayed source sample.
Finally, installer OBS discovery assumed a conventional Program Files layout.

## Implementation details

### Run identity and correctness

- Rejects duplicate names as **username taken**, returns the client to Offline,
  and permits a clean retry under another name.
- Assigns every attempt a bounded `runId`, ignores late events from replaced
  attempts, and accepts duplicate start delivery idempotently.
- Matches Beatblock's real Mine/MineHold counter update order.
- Advances sequence numbers only after a cumulative update enters the bounded
  IPC queue. Rejected telemetry records an integrity reason without dropping
  the game/runtime pipe.
- Publishes a normalized terminal snapshot at the Results boundary so the last
  accepted scoring opportunity is not lost.
- Separates competitive INVALID from DNF. Explicit quit, incomplete finish,
  launch timeout, and disconnect expiry remain DNF even when Run Checks are
  disabled.
- Preserves verdicts through authenticated reconnect and exposes full reasons
  through paginated Results and **Run Details**.

### Room policy and native cleanup

- Adds host-controlled **Run Checks**. Competitive rooms invalidate retries and
  unrecoverable gaps; casual rooms replace a retried attempt and recover from
  cumulative updates while still rejecting impossible counters.
- Clears retained native Player/entity state when leaving Online so it cannot
  continue updating beside the destination state's Player.

### OBS and installer

- Sources accuracy, totals, average timing offset, and the Results marker from
  the same delayed player sample used by the video frame.
- Uses Beatblock's default Cranky costume in disposable renderer profiles.
- Clears stable Stream A–D text files when a slot or participant disappears.
- Adds an editable OBS path and **Browse...** control. Validation accepts the
  OBS root, `bin`, `bin\64bit`, or `obs64.exe`, carries the normalized root
  through elevation, and remembers successful custom or portable installs.

## Migration and compatibility

Host and Player must use the same release. Existing rooms are not migrated
in-place; restart Online after updating. Portable OBS users must select their
installation before enabling the source. The installer preserves unrelated
mods, OBS scenes/plugins, settings, and match history.

## Validation evidence

Protocol and room tests cover attempt replacement, duplicate start delivery,
reconnect verdict preservation, policy-specific retry behavior, DNF
classification, queue rejection, and native counter ordering. Renderer tests
bind score/Results to delayed source state and verify stale text cleanup.
Installer tests cover accepted path shapes, explicit invalid selections,
elevated handoff, and remembered custom roots.

## Known limitations

Physical multi-network WAN and long-duration four-renderer trials remained
environment-specific certification work. This prerelease did not remove the
need to test portable OBS permissions and capture behavior on the production
machine.
