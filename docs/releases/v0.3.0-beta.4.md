# Beatblock Online v0.3.0-beta.4

`v0.3.0-beta.4` is a compatibility, chart-transfer, dashboard, and broadcast
audio prerelease. It resolves GitHub issues
[#15](https://github.com/DupeisTaken/beatblock-online/issues/15),
[#16](https://github.com/DupeisTaken/beatblock-online/issues/16),
[#17](https://github.com/DupeisTaken/beatblock-online/issues/17),
[#18](https://github.com/DupeisTaken/beatblock-online/issues/18), and
[#19](https://github.com/DupeisTaken/beatblock-online/issues/19).

## What players should download

Most players need only `BeatblockOnlineInstaller.exe` from this GitHub Release.
It embeds the runtime, both supported Lua adapters, the pinned no-console Lovely
Injector, and the native OBS 32 source. The remaining assets support inspection
and manual installation:

- `beatblock-online-obs.dll`;
- `beatblock-online-standalone-0.3.0-beta.4.zip`;
- `beatblock-online-beatblock-plus-0.3.0-beta.4.zip`;
- `SHA256SUMS.txt`.

## Complete issue changelog

### Forward-compatible Beatblock releases and strict rooms — #15

**Player-visible behavior**

- The installer accepts a structurally valid Beatblock installation instead of
  requiring an executable hash published in advance. An existing Online
  installer can therefore continue to work after routine upstream updates.
- Once Beatblock starts, Online reads the full upstream version label and uses
  its bracketed build token as the room identity. Deterministic version and
  content-digest fallbacks cover changed or missing version labels.
- Rooms require the exact same Beatblock build by default. Hosts can explicitly
  choose **Allow Any** for casual forward-compatibility testing, and can relax a
  strict room before a race without silently making it strict again.
- Build mismatches report both displayed versions and shortened build IDs.

**Hardening and validation**

- The build identity participates in the password-authenticated join handshake,
  before the participant enters the roster.
- Automatic reconnects retain the original normalized build identity; a real
  QUIC regression test covers the strict-room reconnect path.
- Settings, release titles, the compatibility guide, and a dedicated upstream
  compatibility issue template expose the tested baseline and detected build.

### Safer chart-transfer fallback — #16

**Player-visible behavior**

- A Player whose locked custom chart is missing or mismatched can request that
  exact chart from the host instead of being left at an unclear mismatch state.
- Hosts can enable one automatic request per chart lock, while the manual
  request remains available when automatic transfer is disabled.
- The receiver still owns the existing consent decision; enabling automatic
  requests does not bypass chart-download approval.

**Hardening and validation**

- A request must come from a connected, admitted, unverified Player and must
  name the current locked chart hash.
- The host rechecks role, admission, verification, lock identity, and transfer
  policy after the archive-worker queue and again after packaging. A stale
  request cannot survive a room-state change while work is queued.
- Transfer state and error text are reflected in the dashboard and covered by
  protocol, room, command, and deterministic UI tests.

### Visible compatibility and release identity — #17

**Player-visible behavior**

- The Online header shows the Beatblock Online product version instead of
  presenting protocol v3 as if it were the application version.
- Settings has a compatibility view that distinguishes Online version, protocol
  version, tested Beatblock baseline, and the currently detected upstream
  version/build.
- GitHub Release titles include the tested Beatblock baseline, for example
  **v0.3.0-beta.4 for Beatblock 1.7.1a+**, while the machine tag remains plain
  semver for update checks.

**Documentation and validation**

- The compatibility guide explains forward-compatible installation, strict
  room matching, identity fallbacks, and the procedure for reporting a breaking
  upstream update.
- Release-contract tests verify tag/version equality, prerelease handling,
  compatibility-title generation, and tagged-source checkout.

### Setlist readability — #18

**Player-visible behavior**

- Setlist actions were reorganized so add, remove, and next-chart controls stay
  inside the supported 600x360 dashboard.
- Long chart names, variants, statuses, and command text are constrained to
  their columns instead of drawing outside the panel.
- Validation and disabled states remain visible without displacing the primary
  setlist workflow.

**Validation**

- The deterministic Love2D harness checks the redesigned setlist, validation,
  long-error, host, settings, transfer, and broadcast states.
- All 31 versioned screenshots must match at zero differing pixels.

### Per-renderer OBS audio — #19

**Broadcaster-visible behavior**

- Each OBS Player Stream creates a private Application Audio Capture child
  targeting only its stable `Beatblock Online Renderer A-D` process.
- Renderer audio follows the delayed renderer clock, so the per-stream fine-sync
  default is 0 ms and remains independently adjustable.
- The OBS source degrades to video-only when Application Audio Capture is not
  available instead of failing the Player Stream.

**Operational detail and validation**

- Stable renderer process labels preserve A-D source assignments across normal
  scene and source recreation.
- The native OBS build includes a target-selection test, while source and
  localization checks cover the private child and user-facing controls.
- Windows process-loopback capture copies audio; it does not silence the same
  renderer session on the desktop. Broadcasters must mute each renderer session
  in Volume Mixer or route it to a non-monitored output.

See the detailed routing and verification procedure in the
[OBS setup guide](../obs-setup.md).

## Additional release-review fixes

The release review also corrected SDL3 renderer minimization handling, moved
fallback game-content hashing off the asynchronous runtime and bounded it to a
64 KiB buffer, and closed a chart-transfer eligibility race while packaging was
queued.

## Upgrade notes

1. Close Beatblock and OBS.
2. Download and run this release's `BeatblockOnlineInstaller.exe`.
3. Choose **Install / Update** and optionally install the OBS 32 source.
4. Restart Beatblock and OBS.
5. Confirm every participant uses the intended Beatblock build, or explicitly
   choose **Allow Any** only for a casual compatibility test.
6. In OBS, verify each Player Stream's A-D assignment and renderer audio route
   on the production broadcast machine.

The installer preserves unrelated mods, OBS scenes/plugins, settings, and match
history. This is a beta prerelease: physical OBS mixer routing, multi-network
WAN behavior, and long-duration four-renderer operation should be confirmed on
the target event machine.
