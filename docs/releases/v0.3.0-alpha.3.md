# Beatblock Online v0.3.0-alpha.3

`v0.3.0-alpha.3` migrates Beatblock Online to the redesigned session,
chart-transfer, and Commentator broadcast system. It also hardens room
authentication, host authority, local IPC/API access, installer upgrades,
resource ceilings, and release provenance. The OBS renderer now reproduces the
delayed final player view instead of exposing raw palette-index or incomplete
frames.

## Download

Most players need only `BeatblockOnlineInstaller.exe` from the GitHub Release.

The release also contains:

- `beatblock-online-obs.dll` for manual OBS source inspection;
- `beatblock-online-standalone-0.3.0-alpha.3.zip`;
- `beatblock-online-beatblock-plus-0.3.0-alpha.3.zip`;
- `SHA256SUMS.txt`.

The installer already embeds the runtime, both supported Lua distributions, Lovely Injector, and the OBS source. The ZIPs are development artifacts, not additional player downloads.

## Highlights

### Online and Commentator workflow

- Replaces the earlier Online screens with dedicated Room, Setlist, Broadcast, History, Settings, and Help workspaces.
- Adds host-managed Commentator access, chart transfer, participant inspection, persistent selection, and bounded renderer error details.
- Preserves native keyboard callbacks while supporting active keyboard layouts and Unicode-safe Backspace/Delete editing.
- Uses deterministic 600×360 screenshot coverage for 26 dashboard states.

### Synchronized OBS output

- Defaults renderer slots to the final Full competition view at 1280×720, 60 fps, with a 500 ms delayed buffer.
- Publishes the final palette/accessibility-shaded frame and screen-space effects rather than raw palette-index artwork.
- Keeps the player, notes, hit feedback, chart HUD, and Online race HUD while suppressing decorative chart scenery only inside isolated renderer children.
- Reapplies delayed beat, paddle, tap, and material music-clock corrections after hidden-window input.
- Prevents the first sample from bypassing the configured delay and rejects renderer reconfiguration after the synchronized countdown begins.
- Pins renderer canvases to a 1.0 DPI scale so Windows display scaling cannot change the shared-memory frame dimensions.
- Adds a real LÖVE GPU/readback harness that verifies the final shaded 320×180 frame, opaque aspect-ratio bars, frame publication, and drop count.

Configure and assign every OBS stream before starting the synchronized countdown. An active slot can still be stopped during a race.

### Installer and upgrade safety

- Adds reversible direct-launch support for isolated game copies while leaving Steam-managed installations untouched.
- Preserves a compatible existing Lovely Injector and cleans only positively identified legacy Beatblock Together mod/OBS files.
- Detects a running OBS instance before attempting to replace its loaded plugin.
- Improves elevated-helper diagnostics and validates required dashboard/renderer payload contracts during repair.
- Uses the redesigned deterministic installer icon and keeps the local review build at `releases/BeatblockOnlineInstaller.exe`.

### Security and runtime hardening

- Makes room state and scoring host-authoritative: pending participants,
  spectators, and unknown peer message kinds cannot mutate gameplay or publish
  host-owned snapshots.
- Authenticates both sides of the SPAKE exchange and binds the observed
  self-signed QUIC certificate to the password-authenticated transcript.
- Requires an exact, expiring, one-use authorization for chart archives;
  executable/script content always requires separate confirmation.
- Replaces URL query tokens with a 256-bit local bearer credential, exact
  loopback browser origins, and a token-bearing WebSocket subprotocol.
- Uses only an owner-access-controlled Windows named pipe for production game
  IPC, with partial-I/O handling and bounded frames/queues throughout IPC,
  networking, storage, logging, and transfer work.
- Validates elevated installer manifests, OBS markers, and operation status
  paths before privileged filesystem changes.
- Atomically replaces configuration and credential files, bounds every startup
  read, and prunes only runtime-owned logs and cache data.

### Reproducible releases

- Binds the generated OBS DLL to the reviewed `plugin.c` with a versioned SHA-256 provenance manifest.
- Refuses to embed a missing, modified, or stale OBS artifact.
- Keeps release, build, worktree, test, and temporary outputs out of Git.
- Checks that Rust, Node, protocol, Lua, UI fixture, archive, and release-documentation versions remain aligned.
- Requires the pushed release tag to equal the package version, pins every
  third-party GitHub action to a commit SHA, verifies exact ZIP contents, and
  separates read-only builds from environment-gated publication.
- Regenerates protocol v3 deterministically and attests the installer, OBS
  plugin, checksums, and mod archives before publication.
- Runs the pinned RustSec scanner for the supported x64 Windows dependency
  graph; documented platform-only exceptions remain visible in
  `companion/.cargo/audit.toml`.

## Upgrade

1. Close Beatblock and OBS.
2. Download and run `BeatblockOnlineInstaller.exe`.
3. Select the existing game folder.
4. Choose **Install / Update** or **Repair Required Components**.
5. Restart OBS before adding or testing **Beatblock Online Player Stream** sources.

The installer transaction preserves user data and unrelated mods. Use **Restore Game Files** or **Uninstall** from the same installer if rollback is required.

This remains an alpha prerelease. Automated and isolated-machine gates do not replace the documented physical two-machine WAN and long-duration OBS audio/video certification trials.
