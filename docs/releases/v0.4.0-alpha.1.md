# Beatblock Online v0.4.0-alpha.1

`v0.4.0-alpha.1` is a compatibility, chart-transfer, dashboard, and broadcast
audio prerelease. It resolves GitHub issues
[#15](https://github.com/DupeisTaken/beatblock-online/issues/15),
[#16](https://github.com/DupeisTaken/beatblock-online/issues/16),
[#17](https://github.com/DupeisTaken/beatblock-online/issues/17),
[#18](https://github.com/DupeisTaken/beatblock-online/issues/18), and
[#19](https://github.com/DupeisTaken/beatblock-online/issues/19).

## What players should download

Most players need only `BeatblockOnlineInstaller.exe` from this GitHub Release.
It embeds the runtime, both supported Lua adapters, the pinned no-console Lovely
Injector, and the native OBS 32 source. The remaining assets support inspection
and manual installation:

- `beatblock-online-obs.dll`;
- `beatblock-online-standalone-0.4.0-alpha.1.zip`;
- `beatblock-online-beatblock-plus-0.4.0-alpha.1.zip`;
- `SHA256SUMS.txt`.

## Changes

### Forward-compatible Beatblock releases and strict rooms — #15

The installer now accepts a structurally valid Beatblock installation instead
of requiring a published executable hash. Once the game starts, the runtime
uses Beatblock's displayed upstream build token as its identity. Rooms require
that exact build by default, while hosts can explicitly allow any build for
casual compatibility testing. Strict-room automatic reconnects retain the
original build identity.

### Safer chart-transfer fallback — #16

Players can request the exact locked custom chart after local matching fails,
and hosts may opt into one automatic request per lock. Requests require a
connected, admitted, unverified Player and the current lock hash. The host
rechecks those conditions before and after queued archive preparation, while
the receiving player still controls the existing consent decision.

### Visible compatibility and release identity — #17

Settings distinguishes the Beatblock Online version, protocol, tested
Beatblock baseline, and detected upstream build. GitHub Release titles include
the tested Beatblock baseline without changing the semver tag used by update
checks.

### Setlist readability — #18

Long chart, variant, status, and command text now stays within its dashboard
columns at the supported 600x360 logical layout. The deterministic UI gate
covers every updated screen.

### Per-renderer OBS audio — #19

Each Player Stream creates a private OBS Application Audio Capture child that
selects only its stable `Beatblock Online Renderer A-D` process. Renderer audio
already follows the delayed renderer clock, so fine sync defaults to 0 ms.
Application Audio Capture remains optional and degrades to video-only when OBS
does not provide it.

Windows process-loopback capture copies renderer output but does not silence it
on the desktop endpoint. Mute each renderer session in Windows Volume Mixer or
route it to a non-monitored output; the default pre-volume OBS capture remains
audible. See the detailed [OBS setup guide](../obs-setup.md).

## Review fixes included in this alpha

The release review also corrected SDL3 renderer minimization handling, moved
fallback game-content hashing off the asynchronous runtime and bounded it to a
64 KiB buffer, and closed a chart-transfer eligibility race while packaging was
queued.

## Upgrade notes

1. Close Beatblock and OBS.
2. Download and run this release's `BeatblockOnlineInstaller.exe`.
3. Choose **Install / Update** and optionally install the OBS 32 source.
4. Restart Beatblock and OBS.
5. Confirm every participant uses the intended Beatblock build, or explicitly
   choose **Allow Any** only for a casual compatibility test.
6. In OBS, verify each Player Stream's A-D assignment and renderer audio route
   on the production broadcast machine.

The installer preserves unrelated mods, OBS scenes/plugins, settings, and match
history. This is an alpha prerelease: physical OBS mixer routing, multi-network
WAN behavior, and long-duration four-renderer operation should be confirmed on
the target event machine.
